# 排错

按现象找原因。多数「看起来是 bug」的情况都在这里。

## 启动与构建

| 现象 | 原因 / 做法 |
| --- | --- |
| `npm run tauri:dev` 报 `failed to run 'cargo metadata' ... No such file or directory` | 机器上没有 Rust。装 rustup + 平台 C 工具链，步骤见 [build.md 环境准备](build.md#1-环境准备) |
| 链接阶段报 `link.exe not found` | Windows 缺 MSVC 生成工具。`rustup` 不会代装，要单独装 Build Tools（「使用 C++ 的桌面开发」），同上 |
| 外壳空白 / 按钮点了没反应 | 先跑 `npm run test:ui-module`，它能抓到「模块顶层求值就抛错」这类白屏。也确认是用 `tauri:dev` 起的——单独跑 Vite 没有 Rust 命令，按钮自然不会响应 |
| `npm start` 报 `fetch failed` 或 `Electron failed to install correctly` | 这是 Electron 回退版。二进制没下下来，设 `ELECTRON_MIRROR` 后重跑（见 [README](../README.md) 的回退路径一节） |
| 改了 `assets/logos` 但标签 logo 没变 | 跑 `npm run icons` 重新生成（会同时刷新根目录和 `src-ui/public/`），再重启应用 |
| 打包后标签栏的 logo 全是破图 | 确认 `src-ui/public/icons/` 有文件，且 `npm run check:icons` 通过 |

## 标签与登录

| 现象 | 原因 / 做法 |
| --- | --- |
| 某个标签显示「加载失败」 | 网络/代理问题，不是客户端缺陷；点标签重试，或到 ⚙ → 对应服务行打开开发者工具看详细错误 |
| 某个服务一直登录不上 | ⚙ → 对应服务行的开发者工具，看 Network / Console；仍不行就删除并「删除并清除登录数据」后重来 |
| 标签上没有 logo（只有圆点） | 该站点不在内置图标表里（网站 favicon 也没给）。在设置里把 `icon` 字段填成图标 key 即可 |
| 加了新服务，但标签上仍然没有 logo | 图标表按域名匹配，认不出的就退回彩色圆点；把服务配置里的 `icon` 写成图标 key |
| 导入登录信息后还是未登录 | 先点 ⟳ 刷新那个标签；仍然不行说明该站点把令牌放在 IndexedDB 里，只能重新登录一次 |
| 导入提示「请先填写导出时设置的密码」 | 导出时设了密码，在同一个输入框里填上再点导入 |
| 导入提示「服务对不上」 | 目标设备上还没有这些服务，先在 ⚙ 里添加同样的服务（网址同源即可） |
| Google 登录提示「此浏览器或应用可能不安全」 | Google 对嵌入式浏览器的策略，属于上游限制。改用邮箱密码或手机验证码登录 |

## 分屏与窗口

| 现象 | 原因 / 做法 |
| --- | --- |
| 点 ⇔ 分栏按钮没弹菜单 | 这个菜单还没接上（见 [README](../README.md) 的已知限制）。加减分屏栏请**右键点标签** |
| 标签栏空白处右键没反应 | 外壳右键菜单也还没接，同上 |
| 分屏加不进更多栏 | 窗口太窄，一栏最小 260px；拉宽窗口或先减少栏数 |
| 分屏位置飘了 | 上游 bug（tauri#10131 / #11170），代码里已按窗口事件重算坐标压回去。仍然复现请开 issue 并写明操作步骤 |
| 收起标签栏之后找不回标签栏 | 点托盘（macOS 是菜单栏）图标 →「显示 / 隐藏标签栏」。这是关掉标签栏后唯一还能把它放回来的入口 |
| 按老板键隐藏后整个窗口卡住、标题栏变成「未响应」 | 已修复（0.5.x）：Ctrl+, 的注册 / 注销曾经在主线程上做，而 Windows 的 `WM_HOTKEY` 回调本身就在主线程、且插件派发时持着注册表锁，同一线程重入锁就是永久死锁。现在这条路径只往队列里丢单子，真正的拆装全部在独立工作线程上（见 `src-tauri/src/lib.rs` 的 `spawn_shortcut_sync_worker`） |

## 内存与休眠

| 现象 | 原因 / 做法 |
| --- | --- |
| 启动后内存/流量比之前高 | 预加载**默认是关的**。先确认 ⚙ 里「启动时预加载所有标签」没被打开，再看分屏开了几栏 |
| 某个标签看着变淡了 | 它已经休眠（页面进程被释放），点一下就恢复。嫌回收太快就到 ⚙ →「后台标签自动休眠」里调长，或选「不休眠」 |
| 点回一个很久没用的标签，页面重新加载了一次 | 休眠后的正常恢复。地址会回到你上次停的那一页，但页面内的临时状态（比如没提交的表单）不保证还在；正在编辑的内容不会被回收——回收前会先检查输入框 |
| 在跨域 iframe 里写的草稿丢了 | 回收前只在页面主文档里查输入框，少数把输入框放在跨域 iframe 里的站点探不到。介意的话把休眠调长或关掉 |

## 外观

| 现象 | 原因 / 做法 |
| --- | --- |
| 切成浅色主题后，服务页面还是深色 | 预期行为：主题只控制本应用自己的标签栏和面板，各家网站的深浅色由它们自己决定 |
| 某个 logo 在浅色主题下几乎看不见 | 纯白/浅灰的 logo 会自动换 `icons/light` 那套变体，纯黑的换 `icons/dark`（按颜色亮度+饱和度判定）。漏判的可以在 `assets/logos` 里换图，或给服务手填 `icon` |
| 设置面板看起来是灰的 / 半透明 | 早期版本的 CSS 变量在自己引用自己（`--panel-bg: var(--panel-bg)`），属性会被判定无效而透明。现在浅色下面板、卡片、输入框都是纯白 `#ffffff` |
| 想让动效更"安静"或更快 | 动效数值只在 `src-ui/src/styles/variables.scss` 里（`--dur-1/2/3`、`--dur-exit`、`--ease-out/in-out/drawer`），改这一处全局生效；系统开了「减少动态效果」时自动只保留淡入淡出 |
| 操作时感觉有点卡 / 标签栏在闪 | 标签栏按 `key` 复用节点，状态更新只改变化的属性；动效也只动 `transform`/`opacity`。如果仍然明显，先看是不是分屏开了四栏各常驻一个进程 |

## 配置与数据

| 现象 | 原因 / 做法 |
| --- | --- |
| 标签栏乱了 / 想恢复默认七个服务 | 退出应用，删掉 `%APPDATA%\Aihub\config.json`，重启 |
| 配置文件报错后服务列表变回默认 | 配置解析失败（比如手改坏了）。应用会把坏文件备份成 `config.json.bad` 再退回默认值，可以照着它手动恢复 |
| 升级后「扣子」不见了，多出「豆包」 | 内置站点列表升级：扣子由豆包取代（登录数据也一起清了）。想留扣子，在设置里按原来的网址自己加一个 |
| 删了服务，磁盘上还有同名目录 | 勾选「删除并清除登录数据」时内容会立刻清掉，目录留到**下次启动**删（运行期间 WebView2 占着文件句柄）；残留的只是缓存空壳，不含登录数据 |
| 跑自检时提示「已有实例在运行」 | 应用是单实例的，先退出正在运行的窗口再跑 |

## 开发提示（踩过的坑）

**别在主线程上改全局快捷键注册表。** `tauri-plugin-global-shortcut` 在 Windows 上把隐藏窗口建在主线程，
`WM_HOTKEY` 也就派发在主线程；派发时它持着自己的注册表锁调用我们的闭包，而 `unregister` / `on_shortcut`
要拿同一把锁——std 的 `Mutex` 不可重入，同一线程重入即死锁（症状：窗口停在屏幕上、标题栏「未响应」、
终端一行日志都没有）。另外 `app.run_on_main_thread()` 在**主线程上调用不会排队，是当场内联执行**，
所以「投到主线程去改」绕不开这个死锁。要改就只能在独立线程上改，主线程只入队。

**不要用 PowerShell 5.1 的文本 cmdlet 改源码。** `Get-Content -Raw` + `Set-Content` /
`[IO.File]::WriteAllText` 默认按系统 ANSI 码页读写，直接改写本项目的 UTF-8 源码会把中文注释写坏
（表现为乱码 + 换行被吞掉）。要么别用 PowerShell 改源码，要么显式指定编码：

```powershell
Get-Content -Raw -Encoding UTF8 $p
[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($false)))
```

`tools/*.ps1` 这类辅助脚本也建议只用 ASCII 字符。
