# Aihub 官网设计方案

> 状态：第三版视觉方向（v3）。前两版分别是「落地页模板」和「产品说明书」，都不对，原因见第 2 节。
> 实现：`src/pages/index.astro` + `src/pages/changelog.astro`（Astro 7 + SCSS），结构见第 12 节。
> 原型：`preview-v3.html`（首页）、`changelog.html`（更新日志）保留作视觉对照，不参与构建；历史版本 `design-preview.html`、`preview-v2.html` 同样保留。

## 1. 定位

一句话：**把多家 AI 的网页端放进一个窗口。**

不写"AI 聚合平台"，因为那不是它。它是桌面客户端，加载的是官网本身，不带模型、不代理请求。官网要做的事只有三件：

1. 让人一眼看懂这是**一个窗口里的多个 AI**，不是又一个聊天机器人
2. 让人相信它**轻**（装完 3.7 MB / 闲置挂起）
3. 让人**现在就下载**，并且知道装之前有哪些坑

## 2. 为什么前两版都不对

### 第一版：落地页模板

`hero → 三卡 → 三条功能行 → 对比表 → FAQ 手风琴 → 悬浮下载条`，配色换成绿色也没用。这套分区顺序本身就是 2024 年之后 AI 生成站的固定语法，换成什么颜色都还是它。

### 第二版：产品说明书

为了去"AI 味"，我把结构改成了老牌工具站的样子（BBEdit、Sublime、Everything）：H1 写成 `Aihub 0.9.2`、删掉所有卡片、用两栏「左标题 + 右条目」、1px 分割线、等宽字做装饰。结果走向另一个极端——**像一篇 markdown 直接渲染的文档**。

### 判据：AI 味和"文档感"是两回事

实测七个老牌站（Sublime、BBEdit、Panic、Everything、Fork、Tot、ManyTricks）和五个现代站（PixPin、网易 UU 远程、LocalSend、Mos、Raycast），把 CSS 抓下来统计：

| 站点 | H1 | 首屏内容 | @keyframes | 结构 |
| --- | --- | --- | --- | --- |
| Sublime Text | `Text Editing, Done Right`（34px） | 一张 framed 截图 | 0 | 首屏下直接是更新日志 |
| BBEdit 16 | `BBEdit 16` | 5 行正文 + 截图 | 0 | 横向 tab 行代替分区 |
| Everything | `Everything` | 500px 窄栏 + 列表 | 0 | 2×N 大矩形下载按钮 |
| PixPin | `看到的，都能记下来`（≈58px） | 格纸底 + 四散的工具卡片 | 少 | 居中 Hero |
| 网易 UU 远程 | `流畅可靠，就是好用！`（≈64px） | 3D 小物 + 设备合成图 | 少 | 居中 Hero |
| LocalSend | `无需云端即可分享文件。`（≈64px） | 桌面窗口 + 手机叠图 | 少 | 居中 Hero，深底 |
| Mos | `重塑你的鼠标体验`（≈84px） | 纯黑 + 星点，无图 | 少 | 左对齐 Hero |

（Raycast 首屏 headless 抓取被拦，只按已知结构参考，未计入统计。）

结论有三条：

1. **老牌站不是我们的参照。** 它们能省掉视觉，因为有十年口碑。新项目省掉视觉，读者只会觉得没做完。
2. **现代站的共同点不是动效，是"大"**：H1 56–84px、首屏文字 ≤ 3 块、首屏必有一件"可看的东西"（合成图 / 散落的 UI 卡片 / 3D 小物）。
3. **"像文档"的根因是层级全平**：v2 的 H1 48px、H2 30px、正文 15px，全站一个底色、一种宽度、没有叠层、没有氛围底，眼睛找不到落点。

## 3. 视觉方向

**深色首屏 + 暖纸正文。** 上半屏深（`#0B110F`，带一点绿调的近黑），下半屏暖纸（`#F7F5EF`），产品窗口横跨分界线。

理由：深色把白色窗口衬出来，窗口自己成为首屏唯一的"图"，不需要插画；下半屏回到暖纸保证长文可读。也避开了"纯黑到底"的 AI 站套路和"纯白到底"的文档感。

六条硬规则：

1. **字号要敢大**。H1 `clamp(38px, 5.4vw, 74px)`，区块标题 `clamp(30px, 3.4vw, 44px)`，条目 19–31px。层级靠字号差，不靠装饰。
2. **首屏文字不超过三块**：标题、一句副标（≤3 行）、一行微文案（版本/体积/系统）。
3. **必须有一件真东西**：产品窗口是主角，宽 1080px，压过分界线，后面再垫一层"第二个窗口"制造叠层。
4. **氛围底要克制**：深色区两层极慢漂移的光斑（47s / 63s，只动 `transform`）+ 一层 26px 点阵（用 mask 渐隐）。不做粒子、不做彩色 disco、不做鼠标跟随——光斑是给玻璃提供"可透的东西"，不是主角。
5. **圆角分两套**：窗口/卡片 14–16px，按钮 999px 胶囊，图示面板 20px。不要"全部 4px"那种印刷感。
6. **状态信息做成悬挂标签**，不要塞进窗口里的状态条——两枚深色胶囊挂在窗口下缘、跨在明暗分界上，承担"5 个标签 / 2 个已挂起 / 214 MB / Alt+Space / 52 MB"。

### 3.1 深色与浅色的衔接（第三版修订）

第一版是硬切：深色区块的下边缘直接压在暖纸上，中间没有任何过渡。滚动时视线要在两行像素内跨越 90% 的亮度差，**眼睛会累**，这就是"晃眼"的来源。三条规则：

1. **交界处必须有一层 340px 的纸色渐隐**。用多段 stop 逼近缓动曲线（0 → .035 → .10 → .22 → .44 → .70 → .90 → 1），不要两段线性渐变——两段会在中段留下一道灰绿"雾带"。
2. **让窗口压在过渡带上**。深色区结束的位置要比窗口底边高 140px（`.stage{margin-bottom:-140px}`），这样硬边只出现在窗口左右两侧的窄缝里，被窗口自己打断。目之所及没有一条横贯全屏的分界线。
3. **窗口边缘要收得软**。投影从"0 50px 90px"收到"0 44px 80px -44px"，并在截图底部加 58px 的内阴影暗示内容继续；白色窗口直接压在近黑上、边缘带硬投影，是第二处刺眼。

对比带的深色**不做渐隐**。它是横贯全屏的色带，硬边是"分章"的语言；渐隐只用于首屏这种"页面上半 vs 下半"的过渡。

**导航是一块固定材质的玻璃，全程不换皮。** 滚到哪透哪，不做深浅两个变体——那样必然在明暗交界处"跳"一下，而交界正好就压在导航身上。

材质是**压亮的暖白玻璃 + 深字**：`rgba(252,251,246,.5)`（滚动后 `.58`）、`blur(24px) saturate(1.3)`。白色叠层把透上来的底色统一拉到 130–255 这段亮度，黑字于是全场景过 AA：

| 压在什么上 | 透后亮度 | 黑字对比 |
| --- | --- | --- |
| 首屏光斑中心 | rgb(138,149,142) | 5.7:1 |
| 首屏边缘 | rgb(132,136,133) | 5.0:1 |
| 渐隐带中灰 | rgb(189,188,184) | 9.7:1 |
| 纸色正文 | rgb(251,250,247) | 17.6:1 |
| 白色卡片 | rgb(255,255,255) | 18.3:1 |

**0.5 是算出来的下限**，不是拍的：0.42 时首屏只剩 3.9:1，黑字开始发虚。反方向也不行——深玻璃 + 白字在纸色背景上透后约 rgb(142)，白字只剩 1.8:1。所以"一套材质走完全程"只有白玻璃 + 黑字这一个解。

**先有可透的东西，再谈玻璃。** 模糊和折射作用在纯色上，输出还是那个纯色。之前的首屏只有一层 alpha `.16` 的绿光，采样下来导航背后和纯底色差不到 3 个色阶，玻璃透过去没有任何层次——那才是"灰"的真正来源，不是配色问题，也不是白叠层太厚。现在首屏有两团极慢漂移的光斑（`glowDriftA` 47s / `glowDriftB` 63s），只动 `transform`、不动 `filter`。三条约束：

1. **尺寸远超视口**（2200×2400）。渐变的尾端必须落在视口外，否则深色底上能看出一圈椭圆轮廓，那就成了"打了个灯"而不是"环境光"。
2. **中心压在导航与标题之间**，往下快速衰减。正文区（`sub`、CTA）落在 0.05 以下，对比度不受影响。
3. **两团错开周期**，一绿一青。单团是中心对称的，玻璃横移时透出来的只有一个方向；两团叠加才有冷暖两端。

这不是装饰。行业里做玻璃导航的几乎都配这种漂移光斑，原因就是**液态玻璃在纯色背景上会消失**。

**不要整圈描边。** 1px 白描边（`.66`）压在深色首屏上混合出来是 rgb(172) 的亮灰线，比玻璃本身还抢眼；而它在纸色区又完全看不见——只在最不该出现的地方出现。真玻璃也没有侧边描边，边缘的亮度来自顶部高光和折射。`border: 0`。

**顶部高光必须是渐变的。** 原来用 `inset 0 1px 0 rgba(255,255,255,.95)` 配一道占 58% 高度的向下柔光，叠出来上沿是 rgb(250,251,251) 的纯白硬线、往下 30px 一路掉到 135，整条胶囊读起来像"一根带描边的灰条"。现在换成 `linear-gradient(180deg, .42 → .10 @8% → 0 @20%)`，二十来像素内衰减完，像受光而不像描边。

玻璃要成立，靠三样东西，缺一样就变成磨砂塑料：

1. **顶部渐变高光**：不是一条 1px 的线，是二十来像素的过渡。
2. **底边暗线**：`inset 0 -1px 0 rgba(15,22,19,.07)`。上亮下暗才读得出"一片有厚度的东西"。
3. **两层落影**：贴边的近影定形状（`0 2px 5px -2px`），散开的远影托起来（`0 14px 30px -14px`）。浅色区里玻璃和纸几乎同白，全靠这两层影才看得见边界。

**代价仍然要说清楚：首屏上它是一条比背景亮很多的横杠。** 物理上正确（毛玻璃压深色就是发白），拿不到"深色玻璃"那种味道。加了光斑之后它至少能透出墨绿和明暗过渡，不再是一块均匀的灰。若还是觉得碍眼，唯一的出路是让导航在首屏不出现、滚过渐隐带后再淡入——那不是"不切"，是"延后出现"，得重新讨论。

`mix-blend-mode: difference` 能让文字自动反色、彻底不需要判定，但它会把 jade 按钮上的字变成紫红、中文小字边缘发毛，所以没用。

### 3.2 首屏可玩，下方看图

- **首屏的窗口是能操作的**：点标签换站点（换头像色、域名、对话内容、输入框提示），拖中缝改两栏比例。访客十秒内能自己体验"切站点"和"分屏"两个核心动作，比读三段说明有效。
- **下方功能区的面板只做示意图**，不追求"像截图"：分屏 = 两个真实站点图标 + 各两句短话 + 中间一个可拖的把手；键帽 = 真按键；内存 = 三条真实比例的横条。
- 理由：功能区的图示位只有约 460px 宽，把 2237px 的实机截图塞进去，字小到看不清，反而更像假图。**真实截图只有在满宽时才成立**。
- 满宽位给了"田字格实机"（第 5 节第 6 行）：1400px 窗口、四格各带一段真对话，用 CSS 画而不是截图。CSS 版的字重、字号、间距都能控，不受截图分辨率和对方改版影响；标签栏后半段灰掉，一句话说明"8 个标签同时只渲染 4 格"。若之后拿到干净的实机截图，只替换 `FourUp.astro` 的四格内容，外层结构不动。

**分屏的示意只画两格。** 程序里两格是左右并排、中缝可拖；三格是左一右二；四格是田字格，而且网格形态下没有拖拽（Rust 侧 `compute_grid` 在二维形态下返回空的 `dividers`）。所以"可拖"这件事只在两格上成立，示意画两格才对得上；四格的样子放在满宽区，一处只讲一件事。

### 3.3 不做亮色/深色主题切换

**结论：全站只有一套配色，即「深色首屏 + 暖纸正文」的交替方案，不提供主题开关，也不跟随 `prefers-color-scheme` 切换主视觉。**

理由：

1. **明暗交替是骨架，不是皮肤。** 全站节奏是 深 → 纸 → 纸 → 纸 → 深 → 纸 → 深（见第 5 节）。深色首屏的任务是"把白色窗口衬出来"，对比带的任务是"分章"，纸色段落的任务是"长文可读"。做成主题后，深色模式下三个纸色段落要翻深、首屏失去对比，白色窗口变成贴在黑底上的一块贴纸；浅色模式下首屏和对比带翻浅，明暗节奏消失，退回第 2 节说的"markdown 直接渲染"观感。两个方向都要重做一套视觉，而交替这套是三者里唯一成立的——3.1 的全部结论都建立在它之上。
2. **页面里大多数颜色属于"图"，不属于"主题"。** 原型有 101 个唯一色值，`:root` 只收了 18 个。剩余部分里，第三方品牌色（`#4D6BFE` / `#C96442` / `#10A37F`）不能动，首屏窗口内部的 UI 色（标签栏 `#F4F2EB`、气泡 `#EAF3EE`、输入框 `#EDF1EE`、分屏条 `#F5F3EC`）也不能动——那个窗口展示的是 Aihub 长什么样，它是一张图。主题化之前必须先划出"可主题化 / 不可主题化"的边界，而这条边界一旦存在，之后每次修改窗口模拟都要判断是否被主题误伤。维护成本是长期的。
3. **场景不匹配。** 深色模式的真实需求来自长时间停留的界面（编辑器、终端、阅读器）。官网是 3–8 分钟的定向浏览。参照站里做深色的（Mos、LocalSend、Raycast）是因为产品本身是深色界面，官网在跟随产品；Aihub 的外壳是浅色 webview 容器，跟随逻辑不成立。

**但必须做三件小事**，否则系统深色的用户会看到坏掉的页面：

- `html { color-scheme: light }`（当前全站未声明）。不声明时浏览器会把滚动条、`<details>` 箭头、表单控件按系统深色反色，这才是真正刺眼的地方。
- `<meta name="theme-color" content="#0B110F">` 保留，让移动端地址栏跟上首屏。
- 深色区单独配 `::selection` 底色，默认选中色在 `#0B110F` 上对比不足。

**会改主意的唯一情形：文档区。** 文档是长阅读，深色价值成立。但它属于文档子系统——独立 layout、独立开关，与主站视觉无关。前提是文档页足够长、访问量足够大，当前先不做。

### 3.4 按访问者系统切换下载入口

**做的部分**：首屏主按钮（文案 + 体积）、次按钮、按钮下的兼容性小字、顶部徽标的体积、下载区的说明句、三张平台卡的高亮，全部跟随访问者的系统。macOS 用户进来看到的是"下载 macOS 版 5.4 MB"，不是"下载 Windows 版"。

**做法：三段文案全写进 HTML，用 CSS 挑一段显示。**

```html
<a class="btn btn-main" href="#download">
  <span class="os-win">下载 Windows 版 …</span>
  <span class="os-mac">下载 macOS 版 …</span>
  <span class="os-linux">下载 Linux 版 …</span>
</a>
```

`Base.astro` 的 `<head>` 里有一段同步脚本，在首次绘制前把 `data-os` 写到 `<html>` 上；`.os-win / .os-mac / .os-linux` 的显隐由 `html[data-os=…]` 决定。

为什么不用 JS 改 `textContent`：Astro 的 `<script>` 默认是 module（defer），要等 DOM 解析完才跑。那时首屏已经画过一遍了，非 Windows 用户会看到按钮文字从"Windows"跳成"macOS"。CSS 分支在首次绘制前就确定了，这一下不存在。

**判定顺序有讲究**，写错会把手机用户当桌面用户：

1. 先拦移动端（`Android|iPhone|iPad|iPod`）——安卓 UA 里也有 `Linux`，iPad 的 UA 里也有 `Macintosh`，不先排除就会误判成桌面 Linux / macOS
2. 排除 ChromeOS（UA 里同样有 `Linux`）
3. 再依次判 Windows / macOS / Linux，`navigator.userAgentData.platform` 优先，UA 正则兜底

**判定失败就退回 Windows。** 脚本报错、系统未知、移动端、JS 被禁用——全都不写 `data-os`，CSS 的默认分支就是 Windows 那份文案。它是用户最多的一边，也是页面本来的写法，退化到这个结果最不坏。

**下载区的三张卡不重排。** Windows 占 1.5fr 是因为它是主力平台，这是信息不是装饰；按访问者重排会让同一张截图在不同人屏幕上长得不一样，而且 macOS / Linux 卡的内容量撑不起 1.5fr，换过去只会空。所以"优先"只做在视觉权重上：

- 匹配的卡加绿框和"你的系统"标签，Windows 卡撤掉"推荐"角标与绿框
- 匹配卡里**第一个下载项升成绿色按钮**——否则它只有一行文字链接，旁边 Windows 卡即使降级成描边也还是个整宽按钮，主次反而还是反的
- macOS 那条登录态限制（3.1 提到的共用 cookie 存储）跟着卡片走，不等用户滚到页面底部才看见

真正承担转化的是首屏那颗按钮，它已经跟着系统换了。下载区是给"想看看全部选项"的人准备的，不需要在那里争主次。

**不做**：不自动跳转、不记忆用户手动选过的平台。三张卡都在页面上，选错了点另一张就行。

### 3.5 版本、体积、更新日志只信 Release

**做法**：`scripts/fetch-releases.mjs` 在 `prebuild` 里拉一次 GitHub Releases，写成 `src/data/releases.json`；`release.ts` 与 `changelog.ts` 都从这个文件读，页面里不出现任何手写的版本号、体积或文件名。

**为什么不是"改的时候记得同步"**：手写的版本号最多是停在旧版；手写的文件名会直接 404。这一版之前页面上写着 `universal.dmg`、`AppImage`、`.deb`、`.msi`、`SHA256SUMS.txt`，而打包配置里只有 `nsis / app / dmg`，macOS 矩阵也只有 `aarch64`——六个下载项里四个是死链，体积差了 1–2 MB。这类错误肉眼看不出来，只有点下去才知道。

**为什么不在页面里现请求**：公开接口 60 次/小时按 IP 算，挂到每个访客头上很快就空；接口抽风时更新日志会白屏。构建期取一次，产物是静态的，线上 0 个请求。拉不到就沿用仓库里那份（提交在版本库里的 JSON 就是缓存），干净环境里再失败就退回 `release.ts` 里的常量兜底。

**发版之后站点怎么跟上**：`pages.yml` 除了 `website/**` 改动，还监听 `release: published`。发一个 Release，站点自己重建，版本号、体积、文件列表、更新日志一起变，不需要有人想起来去改官网。

**缺平台就不画按钮**：`release.windows / macos / linux` 各带一个 `available`。没有对应产物时，卡片里出现的是一块虚线灰框（"这个版本没有 Windows 包" / "构建步骤见 docs/build.md"），不是一颗点下去 404 的按钮。以后给 CI 矩阵加 Linux，页面不用改。

**代价说清楚**：更新日志的分组标题（新功能 / 修复 / 重构…）来自发版脚本对提交类型的分组，没有手写的"这一版一句话小标题"；文档、测试、构建这几组被过滤掉，不在官网出现。另外 v0.5.3 只有 tag 没有 Release，所以它不出现在列表里——列表就是"能下到的版本"，这是对的，但和 `git tag` 的清单不再一致。

## 4. 文案原则

- **具体数字代替形容词**：不写"极致轻量"，写"装完 3.7 MB"；不写"智能内存管理"，写"闲置 30 分钟释放进程"。
- **第一人称、承认取舍**：`它不自带模型，也不代理你的请求`、`剩下的都是浏览器的活，它做得比这个好`。
- **限制必须写在明面上**（"装之前要知道的"五条）。这是这个项目的人格证明，也是 AI 搜索最愿意摘的句子。**不折、不缩、不藏。**
- **不用**：赋能、无缝、极致、一站式、重塑、重新定义；三连排比；emoji。
- **装饰性排版一律不用**：`01 / 02 / 03` 大字序号、全大写等宽小标签、hairline 框。这三样是"AI 味"的统计学特征。
- **中文断行落在标点上**：`word-break: keep-all` + `overflow-wrap: anywhere` 兜底。默认规则允许任意两字之间断开，实测会断出"不收集你的数/<br>据，对话……"，一个词被劈成两行。短段落（如页脚那句）都加这条。

## 7. 设计 token

样式用 SCSS，token 集中在 `src/styles/_tokens.scss`，编译期替换成字面值：

```scss
$ink: #0b110f;    // 深色区底
$paper: #f7f5ef;  // 正文区底
$card: #ffffff;
$text: #0f1613; $muted: #565f59; $muted-2: #656e69;
$line: #e4e0d4; $line-2: #edeae1;
$brand: #1e5140;  // 浅色区强调：链接、按钮文字
$jade: #5be0a6;   // 深色区强调：主按钮、标题第二行
$jade-2: #38c98c; // 浅色区的小绿点、条形图
$r: 16px;
$ease: cubic-bezier(.2,.8,.2,1);
$ease-soft: cubic-bezier(.22,.8,.28,1);
```

只有两个 CSS 自定义属性留到运行时，因为它们由行内 style 传入、要参与计算：`--d`（进场延迟）、`--w`（条形宽度）。

**纸色底上的对比度基线**（`#f7f5ef`，WCAG 相对亮度公式实测）：

| 用途 | 色值 | 对比度 |
| --- | --- | --- |
| 正文 / 标题 | `#0f1613` | 16.8 |
| 分组标题、链接 | `#1a4738` | 9.6 |
| 条目正文（更新日志） | `#4a534e` | 7.3 |
| 说明文字 | `#565f59` | 6.1 |
| 日期、单位、meta | `#656e69` | 4.8 |
| 白字 / 深绿底 | `#eef4ef` on `#1e5140` | 8.2 |

两条硬约束，改配色时别破：

- **亮绿不能当文字**。`$jade` 在纸色上只有 1.5，`$jade-2` 只有 2.0——远低于 4.5 的门槛。绿色在这套配色里只有两种合法形态：**面**（按钮底、色块、圆点）和**深绿字**（`#1a4738` 起，9.6）。这也是为什么全站看不到"绿色正文"。
- **灰阶两级都必须在 4.5 以上**。旧值 `#6b746f`（4.43）和 `#8b948f`（2.86）在纸色底上会把 12px 的日期和分组标题糊掉；更新日志改用深绿分组标题 + 石墨正文之后，"分不出段"的问题才消失。

文件按区块切分，`global.scss` 用 `@use` 汇总，**输出顺序即优先级**：

| 文件 | 内容 |
| --- | --- |
| `_tokens.scss` | 颜色、字体、布局、缓动 |
| `_base.scss` | reset、`::selection`、`.wrap`、`.eyebrow`、`.sec-h`、按钮、`.tag`、`.cap` |
| `_nav.scss` / `_hero.scss` | 悬浮胶囊导航；首屏与那个可交互窗口 |
| `_sections.scss` | 数字、站点条、三卡、功能两条、键帽、内存条 |
| `_showcase.scss` | 满宽田字格实机 |
| `_compare.scss` / `_download.scss` / `_footer.scss` | 对比带；下载区；页脚 |

### 7.1 容器宽度与对齐

全站只有**两个**内容宽度，第三个数字必须能一眼看出是故意的：

| 用途 | 宽度 | 说明 |
| --- | --- | --- |
| 正文、导航 | `$wrap` = 1120px | 同一个值。导航不是"另一种容器"，它就是内容区 |
| 满宽田字格 | 1400px | 刻意的"展开"。四个格子同时在场是这张图的信息，宽才有冲击力 |

原来导航是 1010px，比内容窄 110px，于是 logo 比正文左缘右移 **43px**。这不是小差别：1440 下两侧各 160px 空白，屏上唯一能对齐的参照就是这一列文字，43px 的偏移在大屏上很显眼。

**对齐的是文字，不是外壳。** 胶囊边缘是软边界（半透明 + 渐变 + 落影），人眼判断它的位置不精确；文字左缘是一列硬像素，错一格都看得出来。所以做法是让 `nav-in` 的 `max-width` 也用 `$wrap`，左内边距取和 `.wrap` 相同的 28px，logo 和标题落在同一条竖线上，外壳顺手也就重合了。

右侧留 14px 而不是 28px：CTA 按钮贴着胶囊右端才有"端点"感，那一路没有需要对齐的实体，压到 28 会让右端发空。

窄屏（≤1120）时 1120 撑不开，改由导航外层补 16px 护边，内边距同时收成 12px，16 + 12 仍等于 28。实测偏差：

| 视口 | 导航外壳 | logo | 内容框 | 内容左缘 | 偏差 |
| --- | --- | --- | --- | --- | --- |
| 1024 | 16 | 28 | 0 | 28 | 0 |
| 1120 | 16 | 28 | 0 | 28 | 0 |
| 1152 | 16 | 44 | 16 | 44 | 0 |
| 1440 | 160 | 188 | 160 | 188 | 0 |
| 1920 | 400 | 428 | 400 | 428 | 0 |
| 2560 | 720 | 748 | 720 | 748 | 0 |

窄屏偏差为 0 是靠"16 + 12 = 28"凑出来的，不是巧合；改任何一个数都要重新对一遍这张表。手机端（≤640）`.wrap` 内边距收到 20、导航护边收到 10，此时是 10 + 12 = 22，比正文多 2px——这个量级在 375px 宽的屏幕上不可辨，不值得为它把护边压到 8px。
| `_changelog.scss` | 更新日志页 |
| `_motion.scss` / `_responsive.scss` | 动效；四个断点 |

- 主按钮**全站只有一个颜色**：深色区与浅色区都用 `$jade`，字色 `#06130D`。
- 白字放在 `#1E5140` 上对比度约 9:1；jade 上的深字约 11:1。
- 字体全部系统栈，**中文不加载 web font**，字体请求为 0。
- 数字与文件名用等宽，正文不用。
- `html{color-scheme:light}` 锁死，不跟随系统深色；`::selection` 分深浅两套（见 3.3）。

## 8. 动效清单

只有这几处，全部 `transform` / `opacity`：

| 位置 | 内容 | 触发 |
| --- | --- | --- |
| Hero 入场 | 标题/副标/按钮/微文案依次上浮 60–260ms 错开，窗口 1.1s 落定 | 加载 |
| 首屏光斑 | 两团径向渐变极慢漂移（47s / 63s），只动 `transform`，给玻璃提供可透的层次 | 无限循环 |
| 区块进场 | 上浮 22px + 淡入，700ms，`--d` 控制同级错开 | IntersectionObserver |
| 导航 | `scrollY > 10` 时玻璃变厚（不透明度 +8%、落影加深），不换色 | 滚动 |
| 按钮 | hover 上移 2px + 绿色投影 | hover |
| 分屏 | 拖动中缝改变两栏比例（**真交互**，不是演示） | pointer |
| 切换站点 | 点标签换掉左栏的站点、域名、对话与输入框提示 | click |

约束：

- `prefers-reduced-motion: reduce` 下全部关闭，元素直接显示。
- 进场元素**初始可见**，只在 JS 加上 `.js` 后才进入隐藏等待态；`IntersectionObserver` 不可用时立刻全部显示。宁可不动，不能白屏。
- 不做 `backdrop-filter` 的尺寸/模糊动画，不做滚动视差，不做 pin。

## 9. 性能预算

构建产物实测（`npm run build`）：

| 项 | 数值 |
| --- | --- |
| CSS（单文件，两页共用） | 29.7 KB 未压缩 |
| HTML 首页 | 29.5 KB，含内联脚本与三份平台文案 |
| logo | 3.5 KB 图标（96px 方图，导航与页脚共用）+ 13.5 KB 完整字标（品牌留档，不进页面） |
| 站点 logo | 8 个 SVG，共 < 20 KB |
| JS 请求数 | 0——三个脚本（`js` 标记、系统检测、交互）都内联进 HTML |
| 系统检测脚本 | 926 字节，在 `<head>` 里同步执行，约 0.1ms |
| web font 请求 | 0 |
| OG 卡片 | 78 KB，只在社交平台抓取缩略图时加载，不进页面 |

约束：

- **首屏无图片请求**：窗口是 CSS 画的。
- **三份平台文案的代价是 +2.5 KB CSS / +2.5 KB HTML**（3.4）。换来的是一次都没被发现的文字替换——如果用 JS 改 `textContent`，非 Windows 用户会看到按钮先画成 Windows 再跳成 macOS。多出来的字节是压缩前，gzip 后约 +1 KB。
- 站点条的灰度用 `filter: grayscale(1)`，不加额外资源。
- **实时模糊只有一处**：导航胶囊。它跟随滚动、每帧重算，所以窄屏（≤760px）把半径从 24px 砍到 12px。不要把 `backdrop-filter` 铺到大面积区块上——1080px 宽的窗口再叠一层玻璃，滚动就开始掉帧。
- **首屏光斑只动 `transform`**，不动 `filter`、不动 `opacity`。对 `backdrop-filter` 或 `filter` 做动画会让浏览器每帧重算模糊，是最拖累滚动的一种写法。`prefers-reduced-motion: reduce` 下由 `_motion.scss` 的全局规则停掉，光斑保留静态位置。
- 目标：Lighthouse 移动端 ≥ 95，CLS 0。

## 10. SEO / GEO 挂点

- `site` + `@astrojs/sitemap` + 动态 `robots.txt` + 每页 `canonical`。
- **canonical 必须带结尾斜杠**：产物是 `changelog/index.html`，线上是 `/changelog/`（GitHub Pages 会把不带斜杠的 301 过去）。写成 `/changelog` 就等于在 sitemap 之外又声明了一个 URL。`Base.astro` 统一补斜杠，面包屑也走同一套。
- JSON-LD：首页 `WebSite` + `SoftwareApplication`（`operatingSystem`、`offers: 0`、`softwareVersion`、`downloadUrl`、`license: MIT`）+ `Organization`；内页把 `SoftwareApplication` 换成 `WebPage`（`isPartOf` 指回站点），更新日志再加 `BreadcrumbList`——内页重复声明同一个软件是噪音。
- OG / Twitter 卡片写全：`og:locale`、`og:image:width/height`（1200×630）、`og:image:alt`。宽高写出来，抓取方不用等图片下完就能排版。
- OG 卡片比 SEO 更直接：发到群里 / V2EX / X 有没有缩略图，点击率差很多。
- `llms.txt`；`robots.txt` **不屏蔽** GPTBot / ClaudeBot / PerplexityBot / Google-Extended / Bytespider。
- 每页开头 40–60 字定义句；参数表、对比表、限制清单都是 AI 爱摘的结构。
- 品牌词被同名仓库稀释，title 用「Aihub — 把多家 AI 的网页端放进一个窗口」，靠长尾词赢。

**构建坑：`backdrop-filter` 会被去重**

`-webkit-backdrop-filter` 和 `backdrop-filter` 并排写，CSS 压缩器判定为重复声明，**只保留最后一条**。写在前面加前缀、标准在后面，产物里就只剩标准版（Safari 全丢）；反过来写就只剩 `-webkit-` 版（Chrome 的 computed 直接是 `none`，玻璃静默失效）。Safari 至今仍只认前缀，所以两条都要，只能用 `@supports` 隔开：

```scss
-webkit-backdrop-filter: blur(24px) saturate(1.3);
@supports (backdrop-filter: blur(24px)) {
  backdrop-filter: blur(24px) saturate(1.3);
}
```

改完必须 `grep backdrop-filter dist/_astro/*.css` 确认两条都在。这个 bug 在代码里看不出来，页面也不报错，只是玻璃变成半透明色块。

- 仓库 Settings → Pages → Source 选 **GitHub Actions**（不是 gh-pages 分支）。
- 推 `main` 且改动落在 `website/**` 时 `pages.yml` 自动构建部署；**发 Release 也会触发一次**（版本号、体积、更新日志要跟着换）；PR 只构建不部署。

**文案数据来源**

- 版本号、日期、体积、文件名、更新日志全部来自 `src/data/releases.json`，它由 `scripts/fetch-releases.mjs` 在构建前从 GitHub Releases 生成。**不要在页面里手写版本号和体积**（见 3.5）。
- `src/data/release.ts` 负责把资产文件名翻译成"这是什么"：`x64-setup.exe` 是安装版、`aarch64.dmg` 是 Apple Silicon 包、`app.tar.gz` 是自动更新包（不给人点）。缺哪个平台的包，`available` 就是 `false`。
- 站点名与品牌色在 `src/data/sites.ts`；第三方品牌色（`#4D6BFE` / `#10A37F` / `#C96442` 等）**不要改**。
- 更新日志的分组（新功能 / 修复 / 性能 / 重构 / 样式）由 `.github/scripts/make-release-notes.mjs` 在发版时按提交类型写好；文档、测试、构建三组在抓取时被过滤，不上官网。
